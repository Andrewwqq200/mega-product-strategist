# Стратег Фабрики продуктов

Папка для работы руководителя цифрового продукта с агентом. Агент сам ведёт задачу от размытой формулировки до стратегий и плана проверки.

## Как начать

1. В Cursor выберите File → Open Folder и откройте именно эту папку. Родительскую папку открывать не нужно.
2. Откройте новый чат в режиме Agent.
3. Напишите запрос обычным языком, даже если он ещё размытый. Внутренние файлы прикладывать не нужно.

Пример: «Хотим запустить сервис для семьи, пока неясно, нужен ли он».

## Как продолжить

Закройте чат. В той же папке откройте новый чат и напишите «продолжай». Историю пересказывать не нужно.

После принятого результата агент сохраняет карточку решения; новые открытые данные присылайте отдельным сообщением, слово «продолжай» карточку не переписывает.

## Когда нужен ответ

Агент спрашивает, какое одно направление брать в стратегии и что исправить в готовом результате. Если запрос не называет одно направление, вопрос будет и об этом. Остановить работу, уточнить задачу или поправить вывод можно своими словами в любом сообщении.

## Ключи

Скопируйте `.env.example` в `.env` и заполните его только у себя на компьютере. Файл `.env` в репозиторий не попадает.

## Инструменты (MCP)

Конфигурация лежит в `.cursor/mcp.json`. После клонирования откройте **Customize → MCP** в боковой панели Cursor, убедитесь, что серверы включены, и при необходимости выполните **Developer: Reload Window**.

| Сервер | Назначение |
|--------|------------|
| **filesystem** | Файлы в `materials/` и в корне проекта (выписки, переданные материалы) |
| **fetch** | Публичные страницы по URL (шаг «Материалы») |
| **pdf** | Текст и метаданные из PDF в проекте и по открытым URL |
| **excel** | Чтение и правка `.xlsx` и `.csv` |

**Зависимости:** установленный **Node.js** (`npx`) и **uv** (`uvx`) для `fetch` и `excel`. При первом запуске пакеты скачиваются автоматически; ключей API для этих серверов не нужно.

На шаге «Материалы» агент выбирает инструмент по виду источника: сайт — `fetch`, PDF — `pdf`, таблица — `excel`, выписки — `filesystem`. Вызов фиксируйте в `journal/log.md` в поле «Инструменты».

## Где что лежит

- Постоянные инструкции агента: `agent/instructions.md`
- Методика: `methodology/`
- Материалы проекта: `materials/`
- Состояние текущей задачи: `task/state.md`
- Журнал работы по задаче: `journal/log.md`. Там видно, что сделано, на каких источниках и правилах, какими инструментами, оценка времени и расхода.
